화이팅 홈페이지 - 간편회원 전환 적용 안내
작성: 2026-10-06

[이번 변경]
1. 새 회원
   - 아이디 / 이름 / 소속 / 비밀번호로 가입
   - 이메일 입력 없음
   - 로그인은 아이디 + 비밀번호

2. 기존 사용자
   - 기존 이메일 로그인은 그대로 유지
   - 예전 비밀번호를 모르면 "기존 사용자 → 새 아이디로 전환"
   - 기존 이메일을 입력하면 과거 다운로드 기록을 새 간편계정과 합쳐서 관리자 화면에 표시
   - 기존 users / downloadLogs 데이터는 삭제하거나 이동하지 않음

3. 비밀번호 분실
   - 아이디 / 이름 / 소속 / 새 비밀번호 입력
   - 관리자 "비밀번호 자동 초기화" ON: 즉시 새 비밀번호 적용
   - OFF: 관리자 페이지에서 승인 후 새 비밀번호 사용
   - 임시 비밀번호 / 이메일 인증 / 기기 확인 없음

4. 관리자
   - 신규 회원 자동 승인 ON/OFF
   - 비밀번호 자동 초기화 ON/OFF
   - 승인 대기 회원 승인
   - 회원 차단/해제
   - 기존계정 + 간편계정 다운로드 기록 통합 표시
   - 자동 초기화 OFF일 때 초기화 요청 승인/거절

[중요 - 딱 한 번 수동 적용]
GitHub에 firestore-rules.txt는 이미 최신 규칙으로 저장되어 있습니다.
Firebase Console → Firestore Database → 규칙(Rules)에서
GitHub의 firestore-rules.txt 전체 내용을 붙여넣고 "게시"를 눌러주세요.

이 규칙을 게시하기 전에도 기존 이메일 로그인/다운로드는 유지되지만,
새 간편회원 가입/아이디 로그인/자동 비밀번호 초기화는 정상 동작하지 않습니다.

[Firebase Authentication]
현재 홈페이지가 사용 중인 Email/Password 로그인을 그대로 사용합니다.
별도의 Anonymous/Google 공급자를 새로 켤 필요가 없습니다.

[데이터 보존]
기존 users 문서 삭제 안 함
기존 downloadLogs 삭제 안 함
기존 Firebase Authentication 사용자 삭제 안 함
기존 이메일 사용자는 계속 기존 로그인 가능

[새로 추가된 Firestore 데이터]
siteSettings/auth
simpleAliases/{아이디}
passwordResetRequests/{요청ID}

[문제가 생기면]
기존 사용자는 login.html → 기존 사용자 → 기존 방식으로 로그인하면 됩니다.
관리자 페이지의 기존 기능과 앱 업데이트 관리 기능은 그대로 유지됩니다.
